app

アプリケーションのビジネスロジックを格納するフォルダ

Http/Controllers

コントローラーを置くフォルダ
ルート（URL）からのリクエストを受け取り、モデルを使ってデータを取得・加工し、レスポンス（画面やJSON）を返す

Models

モデルを置くフォルダ
データベースのテーブルと1対1で対応するクラスを配置
データベースからのデータ取得、保存、更新、テーブル間のリレーションなどをする

Providers

アプリケーションの起動時に、サービスの初期化や結合（サービスコンテナへの登録）を行う設定フォルダ

Services

コントローラーに書ききれない複雑なビジネスロジックや、外部APIとの通信処理などを切り出して整理するためのフォルダ
肥大化したコントローラーをスッキリさせるために使われる

bootstrap

フレームワークの起動やオートローディング設定をするフォルダ

cache

フレームワークが高速に起動するために生成される設定やサービスのキャッシュファイルが保存されるフォルダ

app.php

アプリケーションの基本設定・インスタンス化ファイル
Laravelのアプリケーション本体を生成し、ルーティングやミドルウェアなどのコアな設定を組み上げる

providers.php

アプリケーションが起動する際に、どのサービスプロバイダーを読み込むかを定義・管理しているファイル

config

アプリケーション全体の設定ファイルをまとめたフォルダ

app.php

アプリケーション全体の設定

auth.php

認証（ログイン・権限）の設定

face.php

顔認証の設定

database

データベース関連のファイルを管理するフォルダ

migrations

マイグレーションファイルを置くフォルダ
テーブルの設計書を書いていく

seeders

データベースに「初期データ」や「テスト用のダミーデータ」を自動で投入するためのフォルダ

lang

翻訳ファイルを配置するフォルダ

ja

日本語フォルダ
lang/ja/validation.phpのattributesに追加したい日本語翻訳を入れていく

node_modules

フロントエンドのパッケージマネージャーが依存関係をインストールするフォルダ

@vladmandic/human

Humanのプログラム本体（ソースコード、設定ファイル、モデルデータなど）が保管されているフォルダ
npm install によって外部からダウンロードしてきたHumanのパッケージ一式が収まっている

public

外部から直接アクセスできる公開フォルダ

models/human

ブラウザが実行時にHTTPでダウンロードする学習済みAIモデル（顔認証）の置き場
巨大なデータなのでビルドツールには含めないことでビルド作業が数秒で終わる＆アプリの画面が開いて必要になった瞬間に初めてそのデータだけを個別にダウンロードできる

resources

コンパイル前のjavasciptやcss、ビューなどを置くファイル

css

cssを置くフォルダ

js

javascriptを置くフォルダ

views

ビューを置くフォルダ

views/layouts
レイアウト置き場

views/errors
エラー時（404や500など）に表示するファイル

フォルダ名/ファイル名の付け方
基本的にフォルダ名→コントローラー名、ファイル名→メソッド名で付けます
例）ArticleController::index() → articles/index.blade.php

↓Laravelのコントローラーで標準的に使用される7つのアクション
※これに該当しない処理のファイル名は適当な名前を付けてください

index 一覧表示
create 新規作成フォーム表示
store 新規保存処理
show 詳細表示
edit 編集フォーム表示
update 更新保存処理
destroy 削除処理

routes

アプリケーションのURLルーティングを定義するフォルダ

web.php

ルーティングを書くファイル

storage

ログやキャッシュ、ファイルアップロードなど、アプリケーションが動作する中で一時的・動的に生成するデータを保存するフォルダ

app/private

一般ユーザーから直接アクセスされたくない、機密性の高いファイルを保存
顔写真はここに保存されている

app/public

ユーザーがブラウザから閲覧しても問題ないアップロードファイルを保存

tests

自動テストコードを記述・保存するためのフォルダ

Feature

ユーザー視点での大きな機能のまとまりをテストするファイルを置く

Unit

アプリケーションの最小単位（個別のメソッドやクラス、サービスクラスの特定の計算処理など）を単体でテストするファイルを置く
