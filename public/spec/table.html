テーブル確認方法

XAMPPのShellで、

mysql -u root
use face;
show tables;　//テーブル一覧
SELECT * FROM テーブル名;　//テーブルの中身

もしくは、VS Codeのターミナルで、

php artisan db:table students

テーブル作成

VS Codeのターミナルで、

php artisan migrate

テーブル作り直しは、

php artisan migrate:fresh
Remove-Item -Recurse -Force storage/app/private/faces -ErrorAction SilentlyContinue　//顔写真削除
php artisan cache:clear file　//古い特徴量キャッシュをクリア

テストデータ注入

VS Codeのターミナルで、

php artisan db:seed

テーブルリセット＆データ注入を同時にするコマンド

php artisan migrate:fresh --seed

ログインIDやパスワード

databases/seedersのAdminSeeder.php、TeacherSeeder.phpに書いてある

モデルファイル

１つのテーブルにつき、１つのモデルファイルを作成します

クラス宣言

クラス名は大文字単数形になります（テーブルは小文字複数形）

↓主な継承

Model 標準のEloquentモデル
Authenticatable ログイン認証機能を持つユーザーモデル
Pivot 多対多の中間テーブル用モデル 
class Admin extends Authenticatable

$fillable

一括代入を許可するカラムのリスト
フォームなどのデータを一気にデータベースに登録する際にここで指定したカラム名しか変更・登録できないようブロックされる 

protected $fillable = ['login_id', 'password'];

$hidden

パスワードなど配列やJSONに変換したときに隠したいカラムのリスト

protected $hidden = ['password', 'remember_token'];

casts()

データベースから取得・保存する際に、データの型を自動変換する仕組み
パスワードのハッシュ化、日付の変換などに使われる 

protected function casts(): array
{
    return ['password' => 'hashed'];
}

リレーション定義のメソッド

テーブル同士の関係性を定義する

BelongsTo 多対1の関係
「〜に属している」
BelongsToMany 多対多の関係
HasMany 1対多の関係
「〜を複数持っている」		 
// 受け持ちクラス（0個以上）
public function schoolClasses(): BelongsToMany
{
    return $this->belongsToMany(SchoolClass::class);
}

Attribute

アクセサ・ミューテタ/属性
データベースの値を加工して見せる・保存するときに使う 

// 画面表示用：「月曜 1限」「水曜 3〜5限」（$subject->schedule_label で使える）
protected function scheduleLabel(): Attribute
{
    return Attribute::get(function () {
        $day = self::DAYS[$this->day_of_week] ?? '?';
        $period = $this->period_start === $this->period_end
            ? "{$this->period_start}限"
            : "{$this->period_start}〜{$this->period_end}限";

        return "{$day}曜 {$period}";
    });
}

Eloquentモデル

LaravelでSQLをPHPのシンプルなメソッドで簡単に書ける方法のこと
※Modelファイルを作成していないと使えません

データの取得

$users = Admin::all();    // adminsテーブルの全データを取得
$user = Admin::find(1);   // IDが1のadminを取得
$thursfri = Subject::where('day_of_week', '>=', 4)->get();  // 木金の授業を全て取得

リレーションと効率化

例えば、SchoolClassモデルに以下のメソッドが書かれているときに使えます

public function students(): HasMany
{
    return $this->hasMany(Student::class);  // // 1つのschool_classesは複数のstudentsを持つ
}
$school_classes = SchoolClass::with('students')->get();  // クラスと一緒にそのクラスの生徒もまとめて取得
$school_classes = SchoolClass::withCount('students')->get();  // クラスと一緒にそのクラスの生徒数(sutudents_count)もまとめて取得

件数のカウントはwithCount('〇〇')と書くだけで「〇〇_count」というデータが自動的に作られ、使うことができます

データの新規登録

// 一括代入
Admin::create([
    'login_id' => 1,
    'password' => 'password123',
]);

// インスタンスを作って save
$admin = new Admin();
$admin->login_id = 1;
$admin->password = 'password123';
$admin->save();

データの更新

$admin = Admin::find(1);
$admin->login_id = admin1;
$admin->save();

データの削除

// IDを指定して直接削除
Admin::destroy(1);

// 対象のデータを取得して削除
$admin = Admin::find(1);
$admin->delete();

メソッドチェーンの順番

->get();が１番最後にさえあれば順番は自由です

$classes = SchoolClass::query()
    ->with(['teachers' => fn ($q) => $q->orderBy('name')])
    ->withCount('students')
    ->orderBy('name')
    ->get();

// ↑↓どっちで書いてもok!

$classes = SchoolClass::query()
    ->orderBy('name')
    ->withCount('students')
    ->with(['teachers' => fn ($q) => $q->orderBy('name')])
    ->get();

sessions

ログイン状態など利用者ごとの一時的な情報を覚えておくためのテーブル
ユーザーのブラウザのCookieに対応する情報をサーバー側のこのテーブルに保存
.envにSESSION_DRIVER=databaseと書いてあるのでデータベース保存
また、SESSION_LIFETIME=120 なので120分間操作がないとログインが切れる

id ID
user_id ログイン中の人のID（未ログインなら空）
ip_address アクセス元のIPアドレス
user_agent アクセス元のブラウザの種類
payload 情報の本体
last_activity 最後にアクセスした時刻

face_samples

顔認証用の顔写真テーブル

id ID
student_id studentsテーブル紐付けられている人物のID
image_path 保存先（faces/(student_id)/～.jpg）
embedding AIが顔の画像から作る1024個の数値の並び
並び全体でその人の顔を表し、矢印の向き（コサイン類似度）で似ているかを判断する
dimension 特徴量の数値の個数（次元数）
Humanのfaceresでは1024
model_version Humanのバージョン情報（human-3.3.6-faceres）
created_at 作成日
updated_at 更新日

match_logs

「誰が・いつ・どのような判定結果で顔認証を行ったか」という監査履歴（ログ）を保存

id ID
student_id studentsテーブル紐付けられている人物のID
判定に合格しなかったときも、一番似ていた生徒のIDが入る
similarity どれだけ似ているか（0~1）
margin ２番目に似ていた人との差
accepted 成功したか（0 or 1）
model_version Humanのバージョン情報（human-3.3.6-faceres）
teacher_id 出席受付をした教師
照合テストでは空
created_at 作成日

データベースに照合結果を保存する理由
①不正アクセスやなりすましを追跡しやすい
②システムの運用基準を最適化するデータとして活用できる
③モデルバージョン変更時の互換性チェック
