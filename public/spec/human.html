Human

Humanとは？

オープンソースのAIライブラリ（@vladmandic/human）で、TensorFlow.jsなどをベースにしている
顔検出・3D顔の向きの追跡（Face Detection & Rotation Tracking）、顔のメッシュ（特徴点）や虹彩（Iris）の検出、顔の記述・特徴量抽出（Face Description/Recognition）、身体のポーズ、手のジェスチャー、感情認識などをWebカメラから検出

faceresとは？

検出された顔から個性を数値化（特徴量ベクトル化）する
顔の画像から、その人固有のパターンを抽出し、AIが認識・比較できるデータ（顔埋め込み：Face Embedding）に変換

導入理由

①高精度な特徴量

従来の軽量ライブラリ（face-api.js など）は128次元だが、Humanは1024次元の高精度なベクトルをブラウザ上でリアルタイム抽出可能
→次元数が多いので識別精度が非常に高く、双子や似た顔、角度や照明が変わっても誤認証が起きにくい

②エッジ処理

ユーザーのPCやスマホのGPU/CPUを使ってブラウザ内で計算するため、Laravelサーバー側は軽量な数値データ（JSON）と画像を受け取って保存・検索するだけで済む
→サーバーに高価なGPUサーバーを用意する必要がなく、インフラコストを大幅に抑えられる

③通信量の小ささ

カメラ映像の全フレーム（動画）をサーバーに送信し続けるのではなく、ブラウザ上で顔が検出された瞬間の「特徴量（数値配列）」だけを送信
→通信量が非常に小さく、照合処理も爆速

④マルチバックエンド対応

GPUのある環境ではWebGL（GPU加速）を使って高速処理し、GPUのない環境では自動的にWASM（WebAssembly）によるCPU処理へ切り替わる
→動かないというトラブルを防ぐ

⑤アップデート

TypeScriptベースで記述されており、TensorFlow.js の最新エコシステムに追従して更新されている
→常に最新の状態

⑥なりすまし防止

瞬きや視線・表情の動きなど生きている人間特有の動きを検知
→「他人の写真」や「スマホの画面」はブロックされる

⑦追加拡張の容易さ

基本機能だけでなく、開発者が自分の作りたいアプリに合わせて新しい機能や設定を簡単に追加・カスタマイズできるよう設計されている

変数

Humanを直接使っているのはresources/js/face-engine.jsのみ
→将来Humanのバージョンが上がったり別のライブラリに変更されたりしても、改修するのはface-engine.jsだけで済む

作成時に渡している設定（new Human({...})）

設定 値 意味
modelBasePath '/models/human/' モデルファイルを置いている場所
backend 'webgl' 計算エンジン（GPUを使う）。使えないPCでは 'wasm' に切り替える
cacheSensitivity 0 前のフレームの結果を使い回さず、毎回検出し直す
face.enabled true 顔の検出を行う
face.detector.rotation true 傾いた顔をまっすぐに補正してから処理する（特徴量の精度向上）
face.detector.maxDetected MAX_FACES（3） 同時に検出する顔の最大数
face.mesh.enabled true 顔の細かい形（468点）を求める。向きの判定と特徴量の精度に必要
face.description.enabled true 特徴量（embedding）を出すモデル（faceres）を使う
face.iris.enabled false 虹彩（黒目）の検出は使わない
face.emotion.enabled false 表情の推定は使わない
face.antispoof.enabled false 写真によるなりすまし判定は使わない
face.liveness.enabled false 生体判定は使わない
body / hand / object / segmentation enabled: false 体・手・物体の検出、背景分離は使わない
gesture.enabled true 「左を向いている」「右を向いている」の判定に使う

呼び出しているメソッド・プロパティ

呼び出し 使っている場所 用途
human.init() init() 計算エンジンの準備
human.load() init() AIモデルの読み込み
human.detect(input) detect() 顔の検出。同時に実行しないよう、順番待ちを経由して呼ぶ
human.models.stats().percentageLoaded init() モデル読み込みの進み具合（0〜1）
human.models.loaded() init() 読み込めたモデル名の一覧。必要なモデルがそろったかの確認に使う
human.tf.getBackend() backendName() 実際に使われている計算エンジンの名前（webgl など）
human.config.backend init() WebGLが使えないときに 'wasm' へ書き換える

検出結果から読み取っている値

human.detect() の戻り値（result）のうち使っている値

値 内容 このアプリでの使い道
result.face 検出した顔の配列 一番大きい顔を照合の対象に選ぶ
result.gesture ジェスチャーの配列（例：{ face: 0, gesture: 'facing left' }） 横を向いていないかの判定
result.error エラー内容 エラーの表示
face.score 顔としての確からしさ（0〜1） MIN_SCORE 未満なら「不鮮明」とする
face.box 顔の枠 [x, y, 幅, 高さ]（ピクセル） 大きさの判定、対象の選択（面積）、顔画像の切り出し
face.boxRaw 顔の枠（0〜1に正規化した値） カメラ映像の上に枠線を描く
face.embedding 特徴量（1024個の数値） サーバーに送って照合・登録する

このアプリ側で決めている値（face-engine.js の先頭）

定数 値 意味
MODEL_VERSION 'human-3.3.6-faceres' 特徴量を作ったモデルの名前。サーバー側の config/face.php と一致させる
MIN_FACE_PX 120 顔の幅がこれより小さければ「近づいてください」と表示する
MIN_SCORE 0.6 face.score がこれより低ければ「不鮮明」と表示する
MAX_FACES 3 同時に検出する顔の数（maxDetected に渡している）
REQUIRED_MODELS ['blazeface', 'facemesh', 'faceres'] 必要なモデル（顔検出・顔の形・特徴量）
GPU_BACKENDS ['webgl', 'humangl', 'webgpu'] GPUを使える計算エンジンの一覧。これ以外ならWASMに切り替える
COLORS 緑・オレンジ・赤・灰色 枠線の色

analyze() は、上の検出結果をこのアプリ用にまとめ直して返します。登録・照合画面では、この戻り値を使っています。

値 内容
ok 照合に使える状態か（true / false）
reason 使えない理由（画面上部に表示する長い文）
short 枠線の横に表示する短い文
face 対象の顔（Humanの検出結果そのもの）
embedding 特徴量の配列（ok が true のときだけ）

取得できるが、今は使っていない値

Humanの検出結果には、ほかにも次のような値があります。

値 内容
face.rotation.angle 顔の向き（左右・上下・傾き）の角度
face.age、face.gender 推定年齢と性別
face.real、face.live なりすまし判定と生体判定の結果。設定で antispoof と liveness を有効にすると得られる
