HumanのWikiページ（Embedding）の翻訳

Embedding（顔の特徴量）についての説明

顔の特徴量(Embedding) と類似度比較

すべての顔埋め込み（Face Embedding）機能のデモは、/demo/facematch で確認できます。

このデモでは以下のような機能を紹介しています：

  • 画像の読み込み
  • 画像からの顔の抽出
  • 顔埋め込み記述子（Face Embedding Descriptor）の計算
  • 顔の類似度の検出と類似度順でのソート
  • 既知の顔リストに基づく最適な顔照合の検出と結果の出力

顔の類似度比較機能を使用するには、比較したいすべての画像に対して埋め込みベクトル（別名：顔記述子）を計算するために、face.description モジュールが有効（デフォルト）になっていることを確認してください。
正確な結果を得るためには、face.mesh と face.detector.rotationも有効にすることを強く推奨します。低品質な入力データで特徴ベクトルを計算すると誤った結果につながる可能性があるためです。
類似度が 50% 以上 であれば、一致（同一人物）とみなすことができます。

コード例:

const myConfig = {
  face: {
    enabled: true,
    detector: { rotation: true, return: true },
    mesh: { enabled: true },
    description: { enabled: true },
  },
};

const human = new Human(myConfig);
const firstResult = await human.detect(firstImage);
const secondResult = await human.detect(secondImage);
const similarity = human.match.similarity(firstResult.face[0].embedding, secondResult.face[0].embedding);
console.log(`顔の類似度: ${100 * similarity}%`);

画像または動画フレーム内に複数の顔が存在し、そのすべてを照合したい場合は、results.face をループ処理します：

for (let i = 0; i < currentResult.face.length; i++) {
  const currentEmbedding = currentResult.face[i].embedding;
  const similarity = human.match.similarity(referenceEmbedding, currentEmbedding);
  console.log(`顔 ${i} の類似度: ${100 * similarity}%`);
}

ただし、デフォルト設定ではフレーム内の最初の1つ目の顔のみを検出するため、検出する最大人数を増やしてください：

const myConfig = {
  face: {
    detector: { maxDetected: 100 },
  },
};

顔記述子 (Face Descriptor)

顔記述子（Face Descriptor）または埋め込みベクトル（Embedding Vector）とは、特定の顔を意図的に一意に識別するために計算された特徴ベクトルの値であり、浮動小数点数の配列として表現されます。
これらは通常の配列として保存し、必要に応じて再利用することができます。

顔の類似度 (Face Similarity)

類似度関数は、ベクトル内のすべての点における一般的なミンコフスキー距離に基づいています。
ミンコフスキー距離とは、各点間の距離のn乗の和のn根です（各記述子は1024個の要素を持つ配列です）。
デフォルトはユークリッド距離であり、これは次数が2の場合のミンコフスキー距離の特例です。
次数を変更することで、類似度マッチングの感度を高くしたり低くしたりできます（デフォルトの次数は2次です）。

例えば、以下はわずかに異なる結果を生成します：

const similarity2ndOrder = human.match.similarity(firstEmbedding, secondEmbedding, { order: 2 });
const similarity3rdOrder = human.match.similarity(firstEmbedding, secondEmbedding, { order: 3 });

顔認識 (Face Recognition)

顔の埋め込み分析を実行した後は、注釈付きの形式で結果を保存しておき、後で任意の顔に対する最適なマッチングを見つけるために使用できます。

例:

const db = [];
const res = await human.detect(input);
db.push({ label: 'this-is-me', embedding: res.face[0].embedding });

同一人物に対して複数のエントリを保持でき、最も一致する結果が使用されます。
最適な照合結果を見つけるには、比較する埋め込み記述子と事前に用意した記述子リストを渡して match.find メソッドを使用します： 

const embeddingArray = db.map((record) => record.embedding); // 埋め込みデータのみの配列を作成
const best = human.match.find(embedding, embeddingArray); // 返り値オブジェクト: { index: number, similarity: number, distance: number }
const label = db[best.index].label;
console.log({ name: label, similarity: best.similarity });

データベースは JS や JSON ファイルに保存し、必要な時に呼び出すことで、任意の数の既知の顔に対応できるように拡張可能な「永久的な顔データベース」として運用できます。
例として、/demo/facematch/facematch.js およびサンプルデータベースの /demo/facematch/faces.json を参照してください：
http/https を使って既知の顔のDBをダウンロードする場合: 

const res = await fetch('/demo/facematch/faces.json');
db = (res && res.ok) ? await res.json() : [];

ローカルファイルから既知の顔のDBをロードする場合 (Node.js):

const fs = require('fs');
const buffer = fs.readFileSync('/demo/facematch/faces.json');
db = JSON.parse(buffer);

顔画像の前処理 (Face Image Pre-processing)

最適な結果を得るために、Human は特徴ベクトル（Embedding）を計算する前に画像に対して以下の操作を実行します：

  • 顔領域の切り抜き (Crop)
  • おおよその顔の角度を検出し、顔を正位置に補正
  • メッシュ（Mesh）の検出
  • 正確な顔の角度を検出し、再度顔を正位置に補正
  • より狭いマージンで再度切り抜き
  • 配色の違いによる影響を排除するため、画像をグレースケールに変換
  • すべての画像について明暗（明るさ）を全領域へ正規化

デモ (Demo)

human.matchではなく、FaceMatcherで計算する理由

↓サーバー照合を採用した理由

  1. 個人情報保護（セキュリティ）

    ブラウザで計算すると個人情報である特徴量をブラウザにダウンロードする必要があるから
    サーバー側で計算することでブラウザに届くのは判定結果だけに制限される

  2. 不正申請の防止（耐改ざん性）

    出席確認の「学生IDが一致しました」のリクエストは開発者ツールから誰でも同じものを作れるので偽装される恐れがある
    特徴量（数値の並び）のみをブラウザに送れば誰なのかはサーバーが決めて記録する

  3. 設定管理とログの一元化

    閾値を.envで管理すれば再ビルド不要
    管理者の照合テストも教師の出席受付も同じFaceMatcherを通るから画面によって判定が食い違わない
    すべての照合がmatch_logsに残るからあとで閾値を見直せる

  4. 高度な判定ロジック（誤認証対策）

    human.match.findは一番近い1件（index、distance、similarity）しか返さないので1位と2位の差も求めるには不適
    また、human.match.findはmodel_versionを確かめて違うモデルの特徴量どうしを比べないようにする計算ではない

↓計算方法をコサイン類似度にした理由
human.match.similarity は、距離を調整用の数（multiplier 25、min 0.2、max 0.8）で 0〜1 に引き伸ばした値のため「0.6がどのくらい似ているのか」を説明しにくい
一方、コサイン類似度は「2つのベクトルの向きがどれだけそろっているか」を表す一般的な尺度であり、長さを1にそろえれば似ている順番はユークリッド距離と同じになる

↓ブラウザで計算する方法との比較

ブラウザで human.match サーバーで FaceMatcher（このアプリ）
全生徒の特徴量の扱い ブラウザに配る必要がある サーバーから出ない
出席を決める場所 ブラウザ（書き換えられる） サーバー
しきい値の変更 JSのビルドし直し .envを変えるだけ
照合の記録（ログ） 別に送る仕組みが要る 照合と同時にmatch_logsに残る
ネットが切れたとき 照合できる 照合できない
1回の照合 通信なし 毎回サーバーと通信する
